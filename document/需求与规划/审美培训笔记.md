## 一、核心共识：什么是"AI Slop（平庸样板 UI）"

两个仓库高度一致地指出，模型都基于相同 SaaS 模板训练，缺少指导时每个 AI 项目都会留下这些"AI 味"痕迹：

| AI Slop 特征（必须避免） | 你的站点现状 | 风险 |
|---|---|---|
| 无脑用 Inter 字体 | 系统默认字体栈（含 Segoe/苹方），无品牌字体 | 中 |
| 紫→蓝渐变 | 主色 `#6b5b95` 沉静紫 | ⚠️ 命中"AI 紫"嫌疑 |
| 卡片套卡片（card-in-card） | 卡片内再放 tag/badge 区 | 轻 |
| 彩色背景上压灰色文字 | 浅灰底 `#f5f5f3` + 灰字，尚可 | 低 |
| 每个标题上方都有圆角方块图标块 | 无图标块 | 安全 |
| 清一色居中 Hero | 首页 Hero 居中 + 左右对称 | ⚠️ 命中 |
| `bounce/elastic` 缓动 | 无 | 安全 |
| 纯黑/纯灰文字无色调 | 文字 `#1f1f23` 已带色调 | 安全 |

**结论**：你的站点"简约"方向是对的，但已踩中 taste-skill 列举的 2 个典型 slop 信号（居中 Hero、单一 AI 紫），且缺少"设计师级别的克制与个性"。

## 二、taste-skill 核心方法论（三旋钮体系）

### 2.1 三个 Dials（1–10 刻度）

| 信号 | VARIANCE 差异度 | MOTION 动效 | DENSITY 密度 |
|---|---|---|---|
| 作品集（开发者，默认建议） | 6 | 5 | 4 |
| 着陆页/作品集（营销默认） | 7–9 | 6–8 | 3–5 |
| "极简/干净/编辑风/Linear 式" | 5–6 | 3–4 | 2–3 |

**针对你的站点定位**（开发者作品集 + 秋招品牌面）：建议 **VARIANCE 6 / MOTION 4 / DENSITY 3**（克制、专业、不花哨，符合招聘官审美）。

### 2.2 可落地的硬规则（直接用于改造）

1. **字体**：禁用 Inter 作默认。开发者作品集可用 `Geist` / `Space Grotesk`（标题）+ 系统无衬线（正文）。中文保留 `PingFang SC / Microsoft YaHei`。
2. **排版纪律**：Hero 标题 ≤2 行；副文 ≤4 行；首屏文本元素 ≤4（眉标/标题/副文/CTA）；**禁止在 Hero 内放标签墙或信任墙**（你首页 Hero 下方有"技术栈"标签墙 —— 需移到后续 section）。
3. **眉标克制**：每 3 个 section 最多 1 个 `uppercase tracking` 小标。你几乎每个 section 都有 `eyebrow`（技术栈/项目/文章）—— 需削减。
4. **布局多样性**：8 节页面至少 4 种布局族；禁止连续 3 节同构 zigzag。你首页是"标签墙 + 卡片网格 + 卡片网格"三节同构 —— 需差异化。
5. **形状锁**：全页统一圆角体系（你已统一 8/12/16px，✅ 良好）。
6. **色彩锁**：全页单 accent 色，饱和 <80%，**禁 AI 紫**。你用 `#6b5b95` 紫 —— 建议换为更"去 AI 味"的色相（见方案）。
7. **卡片纪律**：仅当 elevation 表层级时用卡，否则用 `border-t` / `divide-y` / 留白。你大量用白卡 + 边框 —— 可改为"细线分隔 + 悬停微动"更显高级。
8. **间距**：密度 3 → 大量留白（`py-32~48` 级）。你 `--space-16:4rem` 顶部留白偏紧，Hero 可加大。
9. **动效**：MOTION 4 → 仅需"悬停物理 + 轻入场"，**必须尊 `prefers-reduced-motion`**。你已有 fade-up，✅ 但需补 reduced-motion 守卫。
10. **禁用 em-dash（—）**：全文零容忍（含标题/正文/按钮）。检查现有文案。
11. **禁用 emoji 作图标**：你目前无 emoji，✅ 良好（坚持用 SVG/Lucide）。

## 三、impeccable 核心方法论（46 条确定性检测 + 流程）

### 3.1 设计上下文驱动（先 init 再 build）

impeccable 强调先写 `PRODUCT.md` / `DESIGN.md` 锁定：
- **品牌面 vs 产品面**：作品集属于"品牌面（营销/落地页）"，受众是**招聘官/技术面试官**，语气应"专业、可信、有作品力"。
- 这一步对应你后续 Agent 项目的 `PRODUCT.md` 模板设计（可作为 Agent 的初始化输入）。

### 3.2 46 条检测规则归类（可自检清单）

| 类别 | 代表规则（节选自文档与 README） | 你的站点 |
|---|---|---|
| 对比度 | 灰文字在浅底对比不足 | 次要文字 `#9a9aa3` on `#fbfbfa` 对比偏低 ⚠️ |
| 排版漂移 | 字号/字重不一致 | 基本统一 ✅ |
| 布局溢出 | 容器过宽/溢出 | max-width 920px ✅ |
| AI 设计痕迹 | 紫色渐变、侧边标签边框、暗色发光、弹跳缓动 | 紫主色 ⚠️，无发光 ✅ |
| 设计系统违规 | 违反 DESIGN.md 令牌 | 暂无 DESIGN.md（建议补） |
| 脆弱动效 | 用 scroll 监听驱动 state | 你仅用 CSS 动画 ✅ |
| 通用质量 | 行宽过长、触摸目标过小、跳级标题 | 链接/按钮够大 ✅；行宽 OK |

### 3.3 命令流程（可复刻到 Agent）

`init`（锁上下文）→ `shape`（规划 UX/UI）→ `build` → `audit`（技术质量）→ `critique`（UX 评审）→ `polish`（润色）→ `live`（浏览器实时迭代）。

## 七、给后续 Agent 项目（作品集生成助手）的设计启示

两个仓库直接成为 Agent 的"审美护栏"：

1. **Agent 的 PRODUCT.md 模板**应强制采集：受众（招聘官/客户）、品牌面 or 产品面、语气、反例参考（AI slop 清单）。
2. **Agent 的输出应内置 detector**：生成页面后用 impeccable 的 46 条规则 + taste-skill 三旋钮做自检，命中 slop 则重生成。
3. **字体/色彩/圆角做成令牌锁**：避免每次生成漂移（你当前 global.css 的 `:root` 令牌体系正是正确的基础，Agent 应继承并强化）。
4. **em-dash / emoji / bounce 缓动**做成"硬拒绝"规则，写入 Agent 系统提示。
